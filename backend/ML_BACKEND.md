# Local text model and prediction API

## Dataset and training

The training dataset and its source, attribution, license declaration, and
privacy note are documented in `data/README.md`. To reproduce training from
the project root:

```powershell
Set-Location E:\PhishShift
.\backend\.venv\Scripts\python.exe .\backend\scripts\train_model.py
```

The script verifies the downloaded dataset's SHA-256 before training. It drops
incomplete rows, removes normalized duplicate messages, and excludes
conflicting-label duplicates before making a stratified 80/20 split with
random seed 42. Its scikit-learn pipeline uses word-level TF-IDF (unigrams and
bigrams) followed by logistic regression. The test split is not used for model
fitting. Actual precision, recall, F1, confusion-matrix counts, false positives,
and false-positive rate are written to `reports/model_evaluation.json`. The
report also stores source/missing/blank/duplicate counts, class counts, the
dataset checksum, and training timestamp. Training syncs aggregate provenance
to MariaDB but never copies dataset message text into `scan_results`.

The fitted artifact is stored locally in
`backend/models/phishshift_text_model.joblib`. Joblib model files can execute
code when loaded; load only the artifact generated by this project's trusted
training script.

## API

Start MariaDB in XAMPP and run the API from the backend directory:

```powershell
Set-Location E:\PhishShift\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
```

- `GET /health/db` verifies the existing MariaDB connection.
- `GET /health/model` checks the local trained artifact and returns its name
  and version, without exposing filesystem paths.
- `GET /api/scans?page=1&page_size=10` returns bounded, newest-first scan
  history. Page numbers are limited to 1,000,000 and page sizes to 100.
  Optional `label=Safe%20Email|Phishing%20Email`,
  `sort_by=created_at|risk_score`, and `sort_order=asc|desc` are validated.
  The history list intentionally excludes submitted message text.
- `GET /api/dashboard/summary` returns real scan counts, class distribution,
  and recent activity for the current account only.
- `GET /api/scans/{scan_id}` returns a single saved result and explanation,
  without returning submitted message text. Unknown IDs return 404.
- `GET /api/model/evaluation` returns an allow-listed subset of the saved
  held-out evaluation report; it does not expose file paths or message content.
- `GET /api/auth/csrf` issues the short-lived CSRF token needed for
  state-changing browser requests.
- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`, and
  `POST /api/auth/logout` implement account and server-side session handling.
- Prediction, scan history, scan details, and model analytics require an
  authenticated session. A user's scan queries are scoped to the authenticated
  user ID, never to a client-supplied ID.
- `POST /api/predict` accepts JSON such as
  `{"message":"Review this message."}`. The message must contain non-whitespace
  text and be no longer than 20,000 characters. The response includes the
  model's predicted label, phishing-class probability, a feature-weight
  explanation, and the saved scan ID. `record_kind` defaults to `user`;
  verification scans are visibly marked in history. No demo scans are seeded
  automatically.

Each successful prediction is stored in `scan_results` using a parameterized
SQL insert. The existing schema stores the submitted message text for scan
history. Keep the local demo database private and avoid submitting sensitive
real-world messages. No message contents or credentials are logged.

Scan history and detail reads use parameterized SQL. They return only scan ID,
predicted label, risk score, timestamp, and (for a detail request) the model
explanation. The database schema and existing scan records are not changed by
these read-only endpoints.

Run the non-destructive authentication migration before starting the API:

```powershell
Set-Location E:\PhishShift\backend
.\.venv\Scripts\python.exe -m scripts.migrate_auth
```

Configure `SESSION_SECRET` with a random value of at least 32 bytes of entropy,
`AUTH_SESSION_TTL_SECONDS` as desired, and `APP_ENV=production` in deployment
so session cookies use `Secure`. Keep all credentials in `backend/.env`.
`AUTH_COOKIE_SAMESITE` defaults to `lax`. If the HTTPS frontend and API are
hosted on different sites, configure `AUTH_COOKIE_SAMESITE=none` together with
`APP_ENV=production`; the application rejects `SameSite=None` without Secure
cookies. A same-site domain or reverse proxy is preferable because browsers may
block third-party cookies. Keep the `FRONTEND_ORIGINS` list restricted to
trusted frontend origins.

The classifier is a baseline trained on a third-party labeled corpus; its
probabilities and explanations are not guarantees or security advice.

The API permits browser requests from the local Vite origins
`http://localhost:5173` and `http://127.0.0.1:5173`. For a separately hosted
frontend, set `FRONTEND_ORIGINS` in the backend process environment to a
comma-separated allow-list of exact trusted origins. Do not use `*` for a
public deployment. Local development through the Vite proxy does not require
cross-origin browser access.

## Aggregate metadata migration and local verification

Apply the additive migration to the existing database:

```powershell
Set-Location E:\PhishShift\backend
.\.venv\Scripts\python.exe -m scripts.migrate_project_metadata
```

It creates a checksum-keyed `dataset_metadata` table, adds a unique model
evaluation version key where safe, and adds `record_kind` to older scan tables
with existing records defaulting to `user`. It does not delete or reset data
and never imports the training corpus into scan history.

To explicitly exercise the live model with six benign/phishing-style messages,
run the following while the API is running:

```powershell
Set-Location E:\PhishShift\backend
.\.venv\Scripts\python.exe -m scripts.smoke_test_scans
```

The command prompts for the local account email and hidden password, requests
confirmation before writing six real predictions, checks that the account's
history is readable, and logs out. It prints actual labels, scores, and scan
IDs but no message contents or password. These persistent records are marked
as `verification` when sent by the smoke test. Do not run it unless you want
these records in that account's scan history.

Website scans are not training examples: they have no verified labels.
Optional retraining uses only the pinned documented CSV, seed 42, and its
stratified held-out test split.

## Run the local account application

Start MariaDB from the XAMPP Control Panel, then run the backend in one
PowerShell window:

```powershell
Set-Location E:\PhishShift\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
```

Run the frontend in a second PowerShell window:

```powershell
Set-Location E:\PhishShift\frontend
npm run dev
```

Open `http://localhost:5173/`, create an account, then use the authenticated
dashboard. Leave `VITE_API_BASE_URL` unset for local development; Vite proxies
API and health requests to `127.0.0.1:8765`. For another local backend port,
set `VITE_DEV_API_PROXY_TARGET` in `frontend/.env.local` without adding any
database credentials there.
